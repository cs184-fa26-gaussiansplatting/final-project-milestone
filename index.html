Converting 3D Meshes to 3D Gaussian Splats

Team: Travis Le (CS184), Andrew Kim (CS184), Bharagth Ravindhran (CS184), Emma Yang (CS184)

Webpage · GitHub repository · Milestone video (coming soon) · Milestone slides (coming soon)

Summary

We are building a pipeline that converts a 3D mesh into a 3D Gaussian splat, allowing the model to be viewed with lighting and textures in real time. For this milestone, we completed the pre-training half of the pipeline end to end: we sample a mesh into a point cloud, render reference views with Blender, convert those points into an initial Gaussian representation, and visualize the result.

Current Progress

Our current implementation begins with an .obj mesh and its material file. We are using the mesh area and barycentric coordinates to sample 10,000 points while avoiding degenerate faces. We then use Blender to render eight reference images from cameras arranged around the model and save their camera parameters for the later training stage.

Finally, we convert each sampled point into a Gaussian with a position, spherical-harmonic color, scale, rotation, and opacity, and write the result to a SuperSplat-compatible .ply file. We also wrote a simple point-cloud viewer for inspecting the sampled geometry. The sampling, conversion, and viewing tools are our own implementation; gsplat will provide the differentiable rasterization stage in the next phase.

Preliminary Results

  • We sampled 10,000 points from data/test.obj and generated both a NumPy point cloud and a PLY preview.
  • We rendered eight reference images and recorded the corresponding camera parameters.
  • We generated an initial 10,000-Gaussian .ply file that opens in SuperSplat for inspection.
  • Sampling completes in well under a second, and converting the point cloud to the initial splat file is near-instant.

Progress Reflection vs. Plan

This milestone matches our proposal's goal of getting a mesh-to-Gaussian-splat pipeline working with a small number of reference cameras. The main technical challenge was replacing Structure from Motion with controlled renders of an existing mesh. We addressed this by sampling the mesh geometry and placing cameras on an evenly spaced orbit around it. Limiting the initial render to eight views kept the runtime manageable and gave us a complete dataset for the next stage.

The remaining work is the part that turns our initial estimates into an optimized scene. Our next phase is to implement Gaussian parameter optimization, train against the reference renders, and evaluate how well the result preserves the original geometry and appearance. We also plan to study densification and more adaptive camera placement if time permits.
